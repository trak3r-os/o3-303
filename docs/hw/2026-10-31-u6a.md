# Unit session 2026-10-31: UX image U6a (C1: the Config pages 303 and DEEP, MIDI learn on INSTRUMENT), over USB

Prepared, not run. U6a is U5 plus C1 of `docs/UX-PLAN.md` (`606e3c9`, UX-303 5.12 and 5.5): the app's own pages of the kit's Config
screen, 303 (AUTOSAVE, KEYS AT BOOT, LADDER SLEW, PAD LEGEND, RESET PROJECT) and DEEP (FMT MIX, CMB TUNE, CMB FB, WOB RESET, DLY MODE),
the fix that a non-default DEEP value no longer drops the project at boot (D18), and MIDI learn on INSTRUMENT's Shift row; INSTRUMENT's
DEEP page is gone. The kit under it changed nothing in the image since U5 (simulator and test commits only).

The unit is shared with track3r-os sessions: ask their testers before taking it, note the start state and restore exactly it, card
files included. Firmware goes in only by the console's `--put` / `--update`. This image writes to the card under `Apps/o3_303/` (projects,
`last.txt`, and the kit's settings `system.o3s`, which C1's rows create if it is not there) and RECORD writes `Samples/take_nnn.wav`.
Neither the app nor the console can delete a file: FILE DELETE only marks a project folder with an empty `.deleted` file (kit decision
D4) and the folder stays. So ask the maintainer once, before row 9, for a yes or no to each of: new project folders `U6A` and `U6B`
(rows 9 to 13 and 22 to 24), and one 1-bar take (row 26). What this session adds is listed at the end for the maintainer to delete by hand.
