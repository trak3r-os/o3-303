Run 2026-11-06 by the tester session o3-303-88 over the USB console, cut short: rows 1 to 4, 12 and 13 ran, rows 5 to 11 were not run, and the unit stopped answering on USB before the end state (see End state). This round closes what `docs/hw/2026-11-06-b6.md` left open and checks SK8, the slice after that image: OBSIDIAN as the default look, the value in the ENC window with Shift
held, and the new draw budget of 6,000 µs (`docs/SKIN-PLAN.md`, D21). Its results go into the release notes, so a row not run is said to be not run.

Rows marked (eyes) need the maintainer at the unit, and rows marked (ears) need them listening. The tester leaves those rows open and goes on. Every other row runs by the console: `key`, `enc`, `state`,
`leds`, `cpu`, `crash`, `log`, `version`, `files`, `reset`, `skin`, `--shot`.

The unit is shared. Ask for it through Comunicación con agentes, as the session's orchestrator does, and send "libre" there when done. Note the start state and restore it. A source is connected to the
line-in: leave it connected. An install loses the unsaved STATUS LED setting of Config > DISPLAY. Edits happen on `UNTITLED` with AUTOSAVE OFF only, and a `reset` drops them. No RECORD take, and no project
saved: neither the app nor the console can delete what that writes. Deleting a file we did not put there needs the maintainer's ask, so `system.o3s` stays on the card.

**The last round let autosave rewrite the maintainer's `UNTITLED/live.o3a`.** Set AUTOSAVE OFF first, before any edit. Do not put AUTOSAVE back to 10 S on this image: leave that for last, on the row that
says so, and only after every edit is gone. If the console can read a file off the card, keep a copy of `live.o3a` and `system.o3s` in the session's scratchpad before the install. Record both hashes at the
start and the end, and say if either moved.
